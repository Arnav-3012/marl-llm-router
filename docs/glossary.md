# Glossary

Growing terminology reference. Every task adds the terms it introduces, in the same edit as its docs/viva.md entry (CLAUDE.md).

Entry format: **term (symbol)** — plain-English meaning. **Here:** what it means in this project (field, feature, config key, ADR). **More:** where to read more.

Rules for this file:
- Pointers only; no guide text is copied. A value that is not decided yet is never stated: the entry names the ADR or task that sets it.
- The Deep-Dive Learning Guide is not in the repo (docs/guide-errata.md). Guide references below are limited to part letters that the repo's own docs name: Parts A–B (learning gate L1, M0.5.0), Parts C–D (L2, M2.0), Part E (L3, M3.0), B1 (viva.md M0.1), C2, F1, F2, F3, G4, H4 (guide-errata.md). Where no part is named, only a docs or ADR pointer is given. Check part letters against the guide when it is next opened.
- When the guide and an ADR disagree, the ADR applies (docs/guide-errata.md).
- Symbol clashes to watch: **k** is the neighbour visibility radius (Multi-agent) and also the per-request batch coefficient in t_step(B) = t0 + k·B (LLM serving). **λ** is the cost dial in the reward, **λ_arr** the arrival rate and **λ_sat** the saturation rate. Context decides which; this file names them separately.

## LLM serving

- **a (prefill cost per token)** — seconds of prefill work per prompt token that is not already cached. **Here:** the `a` in T = a·(P − P_cached) + Σ t_step(B_i); fitted per server class into profiling/calibration.json (configs/servers.yaml `prefill_cost_per_token`, null until M0.5.5). Never hand-picked (RULES.md #8). **More:** docs/context.md Environment; ADR-003; Guide Parts A–B; M0.5.4.
- **batch size (B)** — number of requests being decoded together in one step on a server. **Here:** B_i is the batch in decode step i; it enters t_step(B) and is how each decode step's cost is split across requests (ADR-014). **More:** docs/context.md Environment; ADR-014; Guide Parts A–B.
- **cache speedup** — how much faster prefill gets when part of the prompt is already in the prefix cache. **Here:** a per-class parameter from calibration.json (configs/servers.yaml `cache_speedup`), used with P_cached. **More:** ADR-003; M0.5.4; Guide Parts A–B.
- **continuous batching** — the server adds and removes requests from the running batch between decode steps instead of waiting for a whole batch to finish. **Here:** the reason service time is a sum over decode steps whose cost depends on the current B; the project models only t_step = t0 + k·B, not batching internals (out of scope, docs/context.md). **More:** docs/context.md Environment and Constraints; Guide Parts A–B.
- **decode** — the phase that generates output tokens one at a time after prefill. **Here:** the Σ t_step(B_i) term of service time, one step per output token; its speed is what TPOT measures. **More:** docs/context.md Environment; Guide Parts A–B.
- **E2E (end-to-end latency)** — time from a request's arrival to its last output token. **Here:** reported in the Latency metrics group (docs/context.md Metrics); not itself an SLA target (the targets are TTFT and TPOT). Computed in sim/metrics.py (M1.20). **More:** docs/context.md Metrics; Guide Parts A–B.
- **GGUF and Q4_K_M** — GGUF is llama.cpp's model file format; Q4_K_M is a 4-bit quantisation scheme that shrinks the model. **Here:** the real fast-class server runs Qwen2.5-3B in this form (configs/servers.yaml `real_model`); the slow-class model is decided in M0.5. **More:** docs/context.md Environment; M0.5.1.
- **interference** — slowdown a request suffers because other requests run on the same server. **Here:** a per-class calibration parameter (configs/servers.yaml `interference`, null until calibration); its exact role in the service-time formula is fixed when sim/server.py is built (M1.7–M1.8). **More:** docs/context.md Environment; ADR-003.
- **KV cache** — the stored attention keys and values of every token already processed, kept so decoding does not recompute them; it grows with each token and is the memory that limits concurrency. **Here:** modelled as a token budget per server (sim/kv_cache.py: admit, release, fullness). Observation feature "own KV fullness". **More:** docs/architecture.md sim.kv_cache; M1.3–M1.4; Guide Parts A–B.
- **KV token budget (capacity)** — the maximum number of tokens a server's KV cache can hold. **Here:** "Capacity = KV token budget" (docs/context.md); configs/servers.yaml `kv_token_budget` from calibration.json. The 80% fullness threshold for the KV reward term is in ADR-014. **More:** docs/context.md Environment; ADR-014.
- **llama-server (llama.cpp)** — the open-source HTTP server we run real models on. **Here:** the source of real timings for calibration (M0.5) and the real backend for the M6 router. **More:** docs/context.md Environment and Pipeline; M0.5.1, M6.1.
- **Metal** — Apple's GPU API; llama.cpp uses it on the Mac. **Here:** the fast class runs on Metal; Docker on macOS cannot use it, hence the `host` compose profile. **More:** ADR-007; docs/context.md Showcase spec.
- **prefill** — the phase that processes the whole prompt in one pass before the first output token. **Here:** the a·(P − P_cached) term of service time; it dominates TTFT for long prompts. **More:** docs/context.md Environment; Guide Parts A–B.
- **prefix cache** — reuse of the stored KV entries of a prompt prefix that was seen before, so only the new part needs prefill. **Here:** sim/prefix_cache.py (hit_tokens, insert); needs a conversation id so a follow-up turn can match a server that holds its prefix (ADR-009). Cache variant adds the prefix-hit fraction to the observation. Capacity is a constructor argument; its value is not decided yet. **More:** ADR-009; docs/architecture.md sim.prefix_cache; M1.5–M1.6.
- **Qwen2.5** — the open model family used for the real servers. **Here:** Qwen2.5-3B Q4_K_M for the fast class (configs/servers.yaml). **More:** docs/context.md Environment.
- **service time (T)** — how long a server takes to serve one request. **Here:** T = a·(P − P_cached) + Σ t_step(B_i); parameters only from calibration.json. The estimate of this value for a specific neighbour is part of the Forward-target rule (ADR-013). **More:** docs/context.md Environment; ADR-003, ADR-013; M1.7–M1.8.
- **SLA (service-level agreement)** — the latency promise a request must meet. **Here:** a request meets its SLA when it meets both its TTFT target and its TPOT target; R_SLA is +10 if met, −10 if a target is missed, −5 if dropped (ADR-010). Values of the targets: see "TTFT/TPOT target". **More:** docs/context.md Agent; ADR-010.
- **step time (t_step(B), t0, k)** — time of one decode step with B requests in the batch. **Here:** t_step(B) = t0 + k·B; t0 and k come only from calibration.json (configs/servers.yaml `step_base_time`, `step_per_batch_time`). This k is not the visibility radius. **More:** docs/context.md Environment; ADR-003; M0.5.4.
- **token** — the sub-word unit an LLM reads and writes; lengths and costs are counted in tokens. **Here:** P and O are token counts; the KV budget is in tokens; TPOT is seconds per output token. **More:** docs/context.md Environment; Guide Parts A–B.
- **TPOT (time per output token)** — average time between output tokens after the first. **Here:** one of the two SLA targets and reported as p50/p95 (p99 if enough requests). **More:** docs/context.md Metrics; Guide Parts A–B.
- **TTFT (time to first token)** — time from arrival to the first output token: queueing wait plus prefill. **Here:** one of the two SLA targets; time spent held by an agent waiting for its turn counts toward it (ADR-013). **More:** docs/context.md Metrics; ADR-013; Guide Parts A–B.
- **TTFT/TPOT target** — the per-request thresholds that define "SLA met". **Here:** fields `ttft_target`, `tpot_target` on the Request and `sla.*` in configs/sim.yaml. Values are not decided: set by ADR in M1.2, from calibration and EDA. ADR-011 keeps λ_sat independent of them. **More:** docs/phase-plans.md M1.2; ADR-011; docs/architecture.md sim.request.

## Queueing

- **arrival rate (λ_arr)** — requests arriving per second. **Here:** the stream sampler takes λ_arr in req/s, not ρ (M0.6); ρ is converted to λ_arr in M1.28. **More:** ADR-011; docs/phase-plans.md M0.6, M1.28; Guide H4.
- **backlog** — requests in the system that have arrived but are not finished. **Here:** the third λ_sat criterion compares in-system count in the last quarter of the arrival window against the second quarter (ADR-011). Held-but-waiting requests also show up as TTFT (ADR-013). **More:** ADR-011, ADR-013.
- **expected wait (Ŵ)** — an estimate of how long a newly accepted request would wait on a server. **Here:** the observation feature "own expected wait" and the `Server.expected_wait()` interface; used for SED-style rules and the Forward target. The exact formula is fixed in M1.7–M1.8, not here. **More:** docs/architecture.md sim.server; ADR-012, ADR-013.
- **FIFO** — first in, first out. **Here:** an agent decides on the oldest request it holds each tick; a deferred request goes to the back (ADR-013). **More:** ADR-013.
- **inter-arrival CV (c_a)** — standard deviation of the gaps between arrivals divided by their mean; 1 for a Poisson process, above 1 for bursty traffic. **Here:** a burstiness measure from the trace EDA (M0.3); whether it becomes a reported or configured quantity is not decided. **More:** docs/phase-plans.md M0.3; BurstGPT entry below.
- **Little's law (L = λ_arr · W)** — in steady state, average number in the system equals arrival rate times average time in the system. **Here:** a simulator sanity check at ρ = 0.5 and 0.8 (M1.30 (ii)). **More:** docs/phase-plans.md M1.30.
- **Poisson process** — arrivals with independent exponential gaps at a constant rate; the memoryless baseline traffic model. **Here:** the reference against which trace burstiness (c_a) is judged; our traffic comes from real traces, not a Poisson generator. **More:** docs/context.md Environment; docs/phase-plans.md M0.3.
- **ρ and λ_sat (load and saturation rate)** — λ_sat is the arrival rate at which the cluster just saturates, and ρ = λ_arr / λ_sat is the load as a fraction of it. **Here:** λ_sat is measured on the global-form SED cluster by completion ratio, drop rate and backlog growth, per trace and cache setting; the thresholds are stated assumptions. ρ ∈ {0.5, 0.8, 0.95} in experiments. The λ_sat value is not known yet: measured in M1.26–M1.28, then recorded in ADR-011. Replaces the guide's λ/Σμ. **More:** ADR-011; docs/guide-errata.md; Guide H4.
- **slack** — how much time is left before a request's target would be missed. **Here:** the observation feature "slack on this server" (docs/architecture.md); the exact formula is fixed with the observation builder (M1.14–M1.15). E6 analyses slack of accepted requests by server class. **More:** docs/architecture.md Observation; docs/context.md Experiments (E6).

## Data and traces

- **Azure LLM Inference Trace 2023** — public production trace of LLM requests (timestamp, prompt tokens, generated tokens), with a conversation and a code file. **Here:** the main traffic source (`traffic.source: azure2023`); it carries no conversation id (ADR-009). Collected 2023-11-11 per data/README.md. **More:** data/README.md; configs/data.yaml; ADR-009; Guide B1.
- **BurstGPT** — public trace of real LLM usage with bursty arrivals; includes Session ID in the v2.0 file. **Here:** burst tests (E5) and, possibly, conversation structure; BurstGPT_3 is needed for Session ID, BurstGPT_1 has none (docs/viva.md M0.1). **More:** data/README.md; configs/data.yaml; ADR-009; Guide B1.
- **ContextTokens / GeneratedTokens** — the Azure trace's columns for prompt length and output length. **Here:** they become P and O (prompt tokens, output tokens) of a Request. BurstGPT's equivalents are Request tokens and Response tokens. **More:** data/README.md; docs/architecture.md data.traces.
- **conversation id** — identifier linking requests that belong to one conversation, so a follow-up can reuse a cached prefix. **Here:** Request.conv_id; the source (BurstGPT Session ID or synthetic sessions over Azure) is undecided: ADR-009 is proposed until the M0.3 findings. **More:** ADR-009; docs/context.md Environment.
- **conversation mode (BurstGPT)** — rows of BurstGPT produced by chat sessions, as opposed to API-mode rows. **Here:** only conversation-mode rows have a Session ID, so only they can support real prefix-cache structure. How large that subset is: found in M0.3 (ADR-009). **More:** docs/viva.md M0.1; ADR-009; data/README.md.
- **held-out traffic** — the part of the trace never used for training or tuning. **Here:** all reported evaluation uses it, with ε = 0 and at least 5 seeds; tuning uses train traffic only. **More:** docs/context.md Metrics; CLAUDE.md Engineering rules; M2.11.
- **normalisation constants** — per-feature scales used to map raw values into [0, 1]. **Here:** 99th percentile per feature, clipped to [0, 1], written to data/processed/normalisation.json (M0.4); the observation builder uses them (M1.14). **More:** docs/architecture.md data.processed; docs/phase-plans.md M0.3.1, M0.4.
- **prompt tokens (P), output tokens (O)** — token counts of a request's input and generated output. **Here:** Request.prompt_tokens, Request.output_tokens; P_cached is the part served from the prefix cache. **More:** docs/context.md Environment; docs/architecture.md sim.request.
- **Session ID** — BurstGPT column grouping requests of one chat session. **Here:** candidate source of conversation id; present only in BurstGPT_3 and only for conversation-mode rows. Fraction of rows with one: measured in M0.1/M0.3. **More:** ADR-009; configs/data.yaml; docs/viva.md M0.1.
- **stream sampler** — code that turns a trace into a seeded stream of Requests at a given arrival rate. **Here:** data/traces.py `sample_stream(trace, rho, seed, split)` in the architecture; per M0.6 it takes a rate in req/s and the same seed gives the same stream. **More:** docs/architecture.md data.traces; docs/phase-plans.md M0.6.
- **train/held-out split** — time-ordered division of the trace into a training part and an evaluation part, with no overlap. **Here:** `traffic.train_split` in configs/sim.yaml (null until M0); built in data/processed.py (M0.4). **More:** docs/phase-plans.md M0.3.1, M0.4.

## RL

- **action histogram** — counts of how often each action is chosen. **Here:** a training-health metric and a gate in M2.12 (more than one action in use); a near-100% share of any one action is the degenerate-policy warning sign. **More:** docs/context.md Metrics; docs/guide-errata.md (G4); docs/phase-plans.md M2.12.
- **action mask** — a boolean vector marking which actions are legal right now; illegal ones are never chosen. **Here:** mask[3] over Accept, Forward, Defer; Forward is masked at k = 0 and at the hop limit, Defer at the defer limit; no legal action means the request is dropped. Break-it (d) removes masking. **More:** ADR-013; docs/architecture.md; M2.16.
- **Adam / Huber loss / gradient clipping** — Adam is an adaptive-step optimiser; Huber loss is squared error for small errors and linear for large ones, so outliers hurt less; gradient clipping caps the gradient norm. **Here:** the optimiser and loss in configs/dqn.yaml (`loss: huber`, `optimizer: adam`, `grad_clip`); learning rate and batch size are not decided: set by ADR in M2.11. **More:** docs/context.md Agent; configs/dqn.yaml; Guide Parts C–D.
- **discount (γ)** — weight on future reward versus immediate reward. **Here:** γ = 0.99 in configs/dqn.yaml, applied once per decision, not per tick (ADR-010). Break-it (c) compares γ ∈ {0, 0.9, 0.99}. **More:** ADR-010; M2.15; Guide Parts C–D.
- **Double DQN** — a DQN variant in which the online network picks the best next action and the target network evaluates it, which reduces over-estimation of Q-values. **Here:** each agent is an independent Double DQN (MLP 7→64→64→3). **More:** ADR-002; M2.5–M2.7; Guide Parts C–D.
- **epsilon (ε, ε-greedy)** — probability of taking a random action instead of the greedy one, to explore. **Here:** ε decays from 1.0 to 0.05 in training (configs/dqn.yaml; decay length not decided: set by ADR in M2.11); evaluation uses ε = 0. **More:** docs/context.md Agent and Metrics; M2.6, M2.11.
- **MLP** — multilayer perceptron, a plain feed-forward neural network. **Here:** the Q-network 7→64→64→3 with ReLU (agents/networks.py). **More:** docs/architecture.md agents; M2.1–M2.2.
- **Q-value (Q, mean Q)** — the network's estimate of the return from taking an action in a state. **Here:** QNetwork outputs three Q-values per observation; mean Q is a training-health metric. **More:** docs/context.md Metrics; Guide Parts C–D.
- **replay buffer** — memory of past transitions from which training batches are drawn at random, which decorrelates consecutive samples. **Here:** per-agent buffer, capacity set in configs/dqn.yaml (context.md range 20–50k); warmup is not decided: set by ADR in M2.11. Break-it (b) removes it. **More:** docs/architecture.md agents; M2.3–M2.4, M2.14.
- **return** — the (discounted) sum of rewards over an episode. **Here:** a training-health metric logged per episode. **More:** docs/context.md Metrics; M2.10.
- **reward (r)** — the scalar feedback an agent learns from. **Here:** per decision transition: shared R_SLA at resolution − λ·C (serving agent) − KV term (serving agent) − β·B_t (every transition) − immediate Defer/Forward costs (values set by a later ADR). **More:** docs/context.md Agent; ADR-010, ADR-014; Guide F3.
- **s′ (next state)** — the observation the agent receives at its next decision after the one that produced the transition. **Here:** not the state at the resolution tick (option (a) was withdrawn); the DDQN target uses γ once per decision. **More:** ADR-010; docs/architecture.md agents.
- **target network** — a slowly updated copy of the Q-network used to compute training targets, for stability. **Here:** part of each DDQN agent; sync rule not decided: set by ADR in M2.11. Break-it (a) removes it. **More:** docs/context.md Agent; M2.7, M2.13; Guide Parts C–D.
- **TD loss** — the temporal-difference error between the current Q-estimate and the bootstrapped target, passed through the Huber loss. **Here:** a training-health metric. **More:** docs/context.md Metrics; M2.7.
- **transition** — one record of experience used for learning. **Here:** Transition(obs[7], mask[3], action, decision tick, reward, next obs[7], next mask[3], truncated); it is pushed to the replay buffer only when both its reward (at resolution) and its s′ (next decision) exist. **More:** ADR-010; docs/architecture.md agents.
- **truncation vs termination** — termination is a natural end of the process (no future reward); truncation is an externally imposed cut-off, where the value of the next state still matters, so the target bootstraps. **Here:** the episode end is truncation: arrivals stop at `episode_ticks`, the cluster drains, then training ends; unresolved requests at the drain horizon count as dropped. Values of the horizon: set in configs/. **More:** ADR-010; M1.2.

## Multi-agent

- **β and B_t (cooperation term)** — B_t is the cluster breach rate over a recent window; β weights its penalty, so every agent feels the cluster's SLA misses, not only its own. **Here:** reward term −β·B_t on every transition, B_t sampled at the transition's decision tick (ADR-014). `beta_coop` is 0.0 in configs/sim.yaml (off); the β value and the window W are not decided: set by ADR in M3.5. E2 compares on and off. **More:** ADR-014; docs/phase-plans.md M3.3–M3.5; Guide C2, F3.
- **centralised DQN** — one DQN that sees the joint observation of all servers and picks a joint action. **Here:** the reference upper bound for E4; the joint-action design is a Proposed ADR in M3.8. **More:** ADR-002; docs/phase-plans.md M3.8–M3.10; Guide Part E.
- **credit assignment** — deciding which agent and which action deserves the credit or blame for an outcome. **Here:** shared R_SLA goes to every agent that acted on a request; cost and KV terms go to the serving agent only; outcomes are credited at resolution with decision-time state. **More:** ADR-004, ADR-010, ADR-014; Guide F3.
- **independent learners** — each agent learns its own policy and treats the others as part of the environment. **Here:** N = 4 independent DDQN agents with per-agent buffers and rewards (M3.2). **More:** ADR-002; Guide Part E.
- **k (visibility radius)** — how far an agent can see its neighbours. **Here:** `observation.k` in configs/sim.yaml, values 0, 1 or full (E4 sweeps); at k = 0 the neighbour feature is 0 and Forward is masked. Not the batch coefficient k in t_step. **More:** docs/context.md Agent; docs/architecture.md Observation; ADR-013; M3.6–M3.7.
- **neighbour mean wait** — the average expected wait of the servers within radius k, the only neighbour information an agent sees. **Here:** observation feature 6 (0 when k = 0). Local heuristics can use only this mean, never per-neighbour values (ADR-012). **More:** docs/architecture.md Observation; ADR-012; M3.7.
- **non-stationarity** — from one agent's view, the environment changes as the other agents learn. **Here:** accepted cost of independent learning (ADR-002); break-it (f) and (g) probe it. **More:** ADR-002; M3.14–M3.15; Guide Part E.
- **observation (7 features)** — what one agent sees each decision, all in [0, 1]: own expected wait, own KV fullness, prompt size, slack on this server, hop count, neighbour mean wait, prefix-hit fraction. **Here:** replaces the guide's 6 features; an idle agent gets 7 zeros and an all-False mask. **More:** docs/architecture.md; ADR-013; docs/guide-errata.md; Guide F1.
- **ParallelEnv (PettingZoo)** — a multi-agent environment API in which all agents act at once and `reset`/`step` return per-agent dicts. **Here:** the shape of sim/cluster.py; pettingzoo is a dev dependency used only for an API-shape test. **More:** ADR-005; docs/architecture.md sim.cluster.
- **partial observability** — each agent sees only part of the cluster state. **Here:** the price of it is measured by E4 (k = 0, 1, full against centralised DQN). **More:** docs/context.md Questions (3); ADR-002; Guide Part E.
- **VDN and CTDE** — value decomposition networks learn a joint Q as a sum of per-agent Qs; CTDE (centralised training, decentralised execution) is the family it belongs to. **Here:** out of scope; VDN is future work. **More:** docs/context.md Constraints; ADR-002.

## Metrics

- **breach rate** — fraction of requests that miss an SLA target. **Here:** an outcome metric; B_t in the cooperation term is the cluster breach rate over the last W steps. How drops count in it is fixed in M1.19 and M3.3. **More:** docs/context.md Metrics; ADR-014; M3.3.
- **cache hit rate** — share of prompt tokens (or requests) served from the prefix cache. **Here:** an outcome metric; the exact definition is fixed in sim/metrics.py (M1.19–M1.20) and is validated on real conversation structure only per ADR-009. **More:** docs/context.md Metrics; ADR-009.
- **cost per request** — average C_j over requests. **Here:** equals the reward's cost term before the λ weight, with the invariant Σ_j C_j = Σ_i c_i × busy_seconds_i (tested in M1.17); class prices not decided: set by ADR in M0.5.6. **More:** ADR-014; docs/architecture.md sim.metrics.
- **drop rate** — fraction of requests that end as dropped. **Here:** outcome metric and one λ_sat criterion (> 1%, an assumption). A drop counts against the last holder in per-server metrics. **More:** ADR-010, ADR-011, ADR-013.
- **goodput** — useful throughput, in the usual sense requests per second that meet their SLA. **Here:** the headline metric; the exact definition is fixed in sim/metrics.py (M1.19–M1.20), not here. **More:** docs/context.md Metrics; M1.19.
- **Jain's index** — fairness measure (Σx)² / (n·Σx²), from 1/n (one holds everything) to 1 (perfectly even). **Here:** reported as an outcome metric; the quantity it is computed over is fixed in M1.19–M1.20. **More:** docs/context.md Metrics; docs/phase-plans.md M1.19.
- **mean ± 95% CI** — average over seeds with a 95% confidence interval for the mean. **Here:** every reported number uses at least 5 seeds, ε = 0, held-out traffic; one seed is never reported, and the best seed is never picked. `mean_ci95` in eval/stats.py; the method is fixed in M4.1–M4.2. **More:** CLAUDE.md Engineering rules; docs/architecture.md eval; M4.2.
- **Pareto frontier** — the set of points where no other point is better in every objective at once. **Here:** (cost, latency) points from the λ sweep in E3; `pareto_front` returns the non-dominated indices. Question 2 asks whether learned agents trace a frontier that fixed rules cannot. **More:** docs/context.md Questions (2) and Experiments (E3); docs/architecture.md eval; M4.3–M4.4.
- **percentiles (p50, p95, p99)** — latency value below which 50%, 95% or 99% of requests fall. **Here:** TTFT and TPOT are reported at p50 and p95, and p99 only if there are enough requests. **More:** docs/context.md Metrics; M1.19.
- **SLA attainment** — fraction of requests that meet both targets. **Here:** outcome metric, also recorded at 0.1 × λ_sat to show the targets are achievable at all. **More:** docs/context.md Metrics; ADR-011.
- **sim-to-real gap** — |sim − real| / real for a metric. **Here:** E7, computed for SED first, then the learned policy and cache-aware. **More:** docs/context.md Metrics; M6.9–M6.10.
- **utilisation** — share of time a server is busy. **Here:** outcome metric from `Server.busy_seconds`; the exact denominator is fixed in M1.20. **More:** docs/context.md Metrics; docs/architecture.md sim.server.

## Project-specific

- **Accept (action 0)** — the holding agent's server serves the request. **Here:** one of Accept, Forward, Defer; it is the transition that carries the cost and KV terms (ADR-014). **More:** docs/architecture.md Actions; ADR-014.
- **Cache-aware (baseline)** — a heuristic that prefers servers that already hold the request's prefix. **Here:** score = overlap − w·load; local and global forms; the local rules and masked-action fallback are written in the ADR-012 amendment (M1.21), and the weight w is not decided. **More:** docs/context.md Baselines; ADR-012; M1.25.
- **cost (C) and cost dial (λ)** — C is the money-like cost of serving a request; λ weights it against SLA reward. **Here:** C_j = class price × service seconds attributed to j (prefill in full, each decode step split across the batch), charged at resolution to the serving agent. `lambda_cost` default is 0.5 in configs/sim.yaml; E3 sweeps λ ∈ {0, 0.25, 0.5, 1, 2}. Not λ_arr or λ_sat. **More:** ADR-014; docs/context.md Experiments (E3); Guide F3.
- **defer (D)** — the action that holds a request back to try again later. **Here:** action 2; a deferred request moves to the back of the agent's queue (ADR-013); masked at the defer limit D (`max_defers`). D is not decided: set in M1 (configs/sim.yaml `max_defers: null`); no phase-plans task names it explicitly, so confirm where it is set. The immediate cost of Defer is set by a later ADR (ADR-010). **More:** ADR-013, ADR-010; docs/architecture.md.
- **drop** — a request that ends with no legal action or unresolved at the drain horizon. **Here:** R_SLA −5 shared by every agent that acted on it; counts against the last holder in per-server metrics only. **More:** ADR-010, ADR-013.
- **entry agent** — the agent where a request first lands. **Here:** chosen uniformly at random, seeded; `entry_rule: uniform` in configs/sim.yaml. **More:** ADR-013; docs/architecture.md.
- **Forward (action 1)** — the agent passes the request to a visible neighbour. **Here:** masked at k = 0 and at the hop limit; the agent decides only whether to forward. **More:** ADR-013; docs/guide-errata.md; Guide F2.
- **Forward target** — the server a forwarded request goes to. **Here:** chosen by the environment: the visible neighbour minimising expected wait plus this request's estimated service time there, ties to the lowest index. **More:** ADR-013; docs/guide-errata.md.
- **heuristic, local vs global** — a baseline policy in one of two forms. **Here:** local = only the 7 observation features, actions in {Accept, Forward, Defer} (`LocalPolicy.act`); global = full cluster state, direct assignment (`GlobalPolicy.assign`). Local forms are the fair peers of the agents; global forms are information-advantaged references and define λ_sat. **More:** ADR-012; docs/architecture.md policies.heuristics.
- **hop** — one Forward of a request from one server to another. **Here:** Request.hops, limit `max_hops: 2` in configs/sim.yaml; a hop-count feature is in the observation. **More:** docs/context.md Agent; docs/architecture.md sim.request.
- **JSQ (join shortest queue)** — send each request to the server with the shortest queue. **Here:** baseline in local and global forms. **More:** docs/context.md Baselines; ADR-012; M1.23.
- **KV term (w_kv)** — a reward penalty for a request whose serving server was nearly full of KV. **Here:** −w_kv × fraction of the request's resident ticks with KV fullness above 80% (`kv_threshold: 0.8`), credited to the serving agent at resolution. w_kv is not decided: set by a later ADR; M1.24 checks the magnitude against R_SLA first. Replaces "−1 per step". **More:** ADR-014; docs/guide-errata.md.
- **N (cluster size)** — number of servers, and so of agents. **Here:** N = 4 in two classes. **More:** docs/context.md Environment; configs/servers.yaml.
- **Po2 (power of two choices)** — sample two servers and take the less loaded. **Here:** baseline in local and global forms; the local rule is written in the ADR-012 amendment (M1.21). **More:** docs/context.md Baselines; ADR-012; M1.23.
- **prefix-hit fraction** — the share of this request's prompt a server could take from its prefix cache. **Here:** observation feature 7, 0 when the cache variant is off (`prefix_hit_enabled`). **More:** docs/architecture.md Observation; ADR-009.
- **R_SLA** — the SLA outcome reward: +10 both targets met, −10 a target missed, −5 dropped. **Here:** credited at resolution to every agent that acted on the request. **More:** docs/context.md Agent; ADR-010; Guide F3.
- **Random and Round-robin** — stateless baselines: uniform choice and cyclic choice. **Here:** need no state, no local/global split. **More:** docs/context.md Baselines; ADR-012; M1.23.
- **server class** — a type of server with its own physics and price. **Here:** fast-expensive and slow-cheap. The count of each is not decided: set by the M0.5.6 ADR; prices and KV budgets likewise. **More:** ADR-003; configs/servers.yaml; M0.5.6.
- **SED (shortest expected delay)** — send each request to the server where it would finish soonest (queue wait plus its own service time). **Here:** the strongest baseline; its global form defines λ_sat and its local form (SED-local) is an approximation using only the neighbour mean, not SED itself. Viva-critical: rewrite from memory (M1.25b). **More:** ADR-011, ADR-012; M1.25.
- **tick (dt)** — one step of the discrete clock. **Here:** all agents act once per tick, at most one decision each (ADR-013). dt is not decided: set by ADR in M1.2 (configs/sim.yaml `dt: null`); it must be small relative to t_step. **More:** ADR-001, ADR-013; docs/phase-plans.md M1.2.
